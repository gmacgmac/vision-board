## Goal State

When this set closes, all of these are true and tested:

1. **One shape everywhere.** The board's seam *is* the host contract's shape (nclite `shared/plugin-host.ts`, copied here
   as a test fixture): a host built to that contract mounts the board and runs its engine with **no adapter**. The board's
   own app uses the same shapes. The seam number is **2**.
2. **A change line in the contract's words.** A board write's tool result carries `_meta['plugin/change']` =
   `{ words, count, subject, reveal }` (`words` one of `board.change.board|card|cards`, listed in the manifest's
   `changeWords`, with their text in `words.json`; `subject` the board id; `reveal` `{ board, cards }`).
3. **Send records acknowledgements.** `chat.send(record)` calls `record(acks)`: a list of `Ref`s (`[]` when none went,
   `null` only with no chat). The answers chip's `resolve` gives `ack: { board, head }`.
4. **Plain refs.** `chat.reveal` / `chat.hasLine` take `{ board, cards: n }`; `events` take any `Ref` (`{}` = catch up;
   `head: 0` = read from the start; `head` = changed through).
5. **Single agent** (flag `singleAgent`, off by default; the host turns it on for the engine and the view): no sign-up,
   any caller id accepted, ids never compared, no grants, no per-agent scoping. Lines are written as the folder's one
   agent (the one already joined, else one the engine joins itself, named by `name()`). The board lock still refuses
   every write.
6. **No polling for other writers** (flag `followOtherWriters`, on by default; the host turns it off): `watch` hears the
   engine's own writes only.
7. **Scoped stylesheet.** Every selector in the plugin sheet starts with `.vb`, a `.vb-` class or a `vb-` element, with no
   `:is`/`:where`/`:not`/`:has` before its first space (nclite's `checkStylesheet` passes with no waiver); `npm run verify`
   holds the rule. A host's own `position` on the root still wins.
8. **The skill** has a one-line description saying when to use the board, and the plugin's `skill.md` is cut toward
   8 KiB, per-tool detail moved into the tool descriptions, with `npm run eval:bot` passing.
9. **Standalone unchanged** for the person: same board, same chat, same pages; the full page suite passes.
10. A handover to nclite names the flags, the commit to vendor, and the two asks (rename `CHANGE_META` to
    `plugin/change`; no sign-up, no stored ids, no special case for old bots).

## Decisions

1. **One shape everywhere** (maintainer, nclite handover "GM's rulings"): the board adopts the contract's shapes in its
   own code for every place it runs, not as a plugin-mode branch. One code path. Seam 1 → 2.
2. **Plugin mode is switches, not forks** (same): behaviour that differs inside a host is an engine flag (and a view
   setting where the view is concerned) the host turns on; standalone leaves it off.
3. **Single agent** (points 484-490): a flag, `singleAgent`. With it on: the engine requires no sign-up and accepts any
   caller id; it never compares ids: no `needs-grant`, no `creator` refusals between agents, `request_grant` answers
   `held`, every read is unscoped (`check_responses`, `list_open`, marks, the answers chip), the view ignores
   `chat.status.agent`. Every agent line is written as the folder's one agent: the first agent already joined in the
   ledger (so an existing bot keeps its boards), else one the engine joins itself on its first write, labelled by
   `name()`. The person's actions stay the person's (✓, ✗, approve), and **the board lock still refuses every write**.
   Off (standalone): as today.
4. **No polling for other writers**: a flag, `followOtherWriters`, on by default; off, `watch` and the held read never
   start `ledger.follow()`.
5. **The change key is neutral** (point 482): `plugin/change`, not `nclite/change`; the handover asks nclite to rename
   `CHANGE_META`. The fixture copy carries that one change, noted.
6. **Change words** keep nclite's legacy keys and text word for word (`board.change.board` "Changed board “{subject}”",
   `board.change.card` "Changed a card on board “{subject}”", `board.change.cards` "Changed {count} cards on board
   “{subject}”"), so a line stored before and one written now read the same.
7. **Reveal refs**: `chat.reveal` / `hasLine` get `{ board, cards: n }` (a number: nclite's `lineMatches` holds a
   number in a line's list).
8. **Standalone's chat feed keeps its own internal shape** (`ChangeEntry`, `tool_activity`): that is a host's inside,
   not the seam. Its bridge speaks the seam's shapes.
9. **No sign-up in plugin mode, kept standalone**: `POST agents` (join) stays for the board's own app and for hosts
   that leave `singleAgent` off.
10. **The skill** (handover C1): the one-line description now; slimming is plugin-only where it can be (skill edits), and
    moves per-tool detail into the tool descriptions where it is about one tool; `eval:bot` (live) passes before it
    lands. If 8 KiB costs behaviour the evals catch, stop at the smallest size that passes and report it.

## Risks & Considerations

| Risk | Mitigation |
|------|------------|
| Seam 2 breaks a host on seam 1 | nclite pins the seam; the handover says vendor and set flags in one change |
| Single agent widens what a bot may write | Only with the flag; the lock and the person-only actions still apply; nclite gives each bot its own folder (D-077 1) |
| A derived id would fail the ledger's agent pattern | Lines are written as the folder's joined agent, never the caller's raw id |
| Slimming the skill loses behaviour | Live `eval:bot` before and after; stop at the smallest size that passes |
| Moving `:where(.vb-board)` changes who wins `position` | The root's position is set so a host's own rule still wins; a page spec proves it |
