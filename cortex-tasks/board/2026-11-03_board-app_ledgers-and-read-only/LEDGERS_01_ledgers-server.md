# LEDGERS_01_ledgers-server: Ledgers on the server

> **Parent**: [TASK-STATUS.md](./TASK-STATUS.md) · **Plan**: [PLAN.md](./PLAN.md)

## Objective

With `ledgerFolders` on, a project holds several ledgers in `.visionboard/<ledger>/`: the server opens, switches and
creates them, takes the lock per ledger, moves an old-layout folder into `main/` once, and can move it back. The
contract changes first. With the flag off, nothing changes.

## Context

PLAN Decisions 1-9 are the rulings; read them first, and PATHS_01's and ACCESS_01's notes. After PATHS_01 every
data-folder path comes from `packages/format/src/data-folder.ts`, so the layout changes there; the rest is how the
standalone server opens a folder (research, 2026-11-03):

- **Switch** (`apps/board/server/project.ts` `openProject().open(dir, create)`): `hasBoard`, `takeLock`, `ledgerOf`

  `ledger`, `agents`, `chats`, `apps`, `closed`. Streams end through `closed` on a switch; the page reloads
  (`apps/board/src/shell/folder.ts` `reloadOnto`, `folderMoved`).
- **Handlers** (`apps/board/server/open-folder.ts` `OPEN_FOLDER`): `getProject`, `listFolders` (`childFolders`,
  `cloudPlaces`, `recent`), `openProject` (refuses home itself); `shown()` gives `{ path, name, found, boards }`.
- **Contract** (`packages/format/schema/openapi.json`): `get_project`, `open_project` on `/api/project`; `list_folders`
  on `/api/folders`; `watch_project` on `/api/events`. Schemas `schema/api/project.schema.json` (`found`, `hasBoard`
  "a .visionboard/ledger.jsonl file", `$defs/folderHeader`) and `open-project-request.schema.json` (`create`).
  Docs: `docs/specification/api.md` § Opening a folder from the board, § The project stream and watch mode;
  `api-reference.md` (generated by `npm run gen`).
- **Agents' reads**: `list_boards` (`packages/actions/src/reads.ts` `boardList`, `list-boards-response.schema.json`)
  and `join` answer `project`, the folder as the person reads it (engine `name()`).
- **Tracked in git in this repo**: `.visionboard/ledger.jsonl`, `.visionboard/.gitignore`, `.visionboard/apps/calculator/*`
  (`apps/board/tests/repo-example-app.test.ts` "this repo's .visionboard/apps/calculator/ is the skill's example…").

## Steps

1. **The layout in the paths module** (`data-folder.ts`): `MAIN_LEDGER = 'main'`; `ledgerNameProblem(name)` (kebab
   id like a board id, at most 40 characters, not a data-folder name: PLAN decision 1), its sentence in format's words
   file; `ledgerFolder(projectDir, ledger?)` gives `.visionboard/<ledger>` when a ledger is named and the legacy root
   when not; `projectOfLedger` handles both. Unit tests for every name rule and both layouts.
2. **Contract first**, under `ledgerFolders` (fields optional, present only with the flag on):
   - `get_project` answers `ledger` (the open one) and `ledgers: [{ name, boards, keptOutOfGit }]`.
   - `open_project` takes optional `ledger` (default: the folder's last ledger, else `main`) and, with `create`,
     `keepOutOfGit` (decision 8). An invalid name is `invalid` at its pointer, in plain words.
   - `list_boards` and `join` answer `ledger` beside `project`, so an agent is told which ledger it is on (D-083 rule 4).
   - Descriptions in the schemas name the layout through the words they already use; `hasBoard` reads "a ledger in
     `.visionboard/`". `npm run gen`; `npm run gen -- --check` clean.
3. **Failing tests first** (`apps/board/tests/api-ledgers.test.ts`, new): open a new-layout folder; list ledgers with
   board counts; create a ledger (and kept out of git: its `.gitignore` is `*`); switch, and the streams of the old
   ledger end; a bad name refused; the lock is the ledger folder's (two ledgers of one folder can be held by two
   servers, one ledger cannot); `list_boards` / `join` answer `ledger`; repo-wide files stay at `.visionboard/`
   (a chat session, an attachment and a permission land there, not in the ledger folder); with the flag off every
   existing test in `apps/board/tests/` passes unedited.
4. **The server**: `server.ts` and `recent.ts` remember the last ledger per folder (extend `recent.json` back-compatibly:
   an old file still reads); `project.ts` `open(dir, { ledger, create, keepOutOfGit })`, the lock taken on the
   ledger folder, `hold` through `projectOfLedger`; `folders.ts` `hasBoard` / `countBoards` see both layouts (a home
   folder holding only `recent.json` is still not a board); `open-folder.ts` `shown()` and `getProject` carry the
   ledgers; `apps/board/server/ledgers.ts` (new, I/O) lists and creates ledger folders, writing the ledger folder's
   own `.gitignore` (`agents.json`, `lock`, `app-state/`) through `agents.ts` `ignoreInGit`. Repo-wide files through
   `projectFiles`. Words in `apps/board/server/words/`.
5. **The move** (`apps/board/server/ledger-move.ts`, new: `moveIntoMain`, `undoMove`): runs from `open` with the flag on
   when the folder is in the old layout. Order: take the old root's lock (refuse with `holderMessage` if live
   anywhere); refuse if `main/` exists; make `main/`; **rename** each per-ledger entry that exists (`ledger.jsonl`,
   `agents.json`, `images/`, `apps/`, `app-state/`) into it; split `.gitignore` (per-ledger names into `main/.gitignore`,
   repo-wide ones stay); take `main/`'s lock; release the root's. Nothing is copied, rewritten or deleted. A failure
   part-way leaves every file in one of the two places and says which, and the next open finishes or reports it.
   `undoMove(project)`: only when `main/` is the only ledger and no live lock; the same renames back.
   `apps/board/bin/ledgers-undo.ts` runs it for a folder argument (`npm run ledgers:undo -- <folder>`, the script
   added by the orchestrator at SETUP). Tests on a copy of a real-shaped folder in the OS temp folder: every byte
   of every file is the same after the move and after the undo; a live lock stops both; a second move is refused.
6. **The equality test** (`apps/board/tests/access-layout.test.ts`, new): for every per-ledger and repo-wide file the
   paths module names, in both layouts, `#agent`'s `accessFor` gives the verdict PLAN decision 2 and ACCESS_01 set
   (secrets refused both ways, the ledger read-only, pictures and apps writable). It fails if a file is added to the
   module without a rule.
7. **This repo's example app**: `repo-example-app.test.ts` finds `apps/calculator/` in either layout.
8. **Docs** (`cortex-docs`): `api.md` § Opening a folder from the board (ledgers, the move, the lock per ledger);
   `images.md` § The folder, `apps.md` § The folder, `chat.md` § Attaching (attachments stay repo-wide);
   `README.md` § Running and `apps/board/README.md` (where a ledger lives, `ledgers:undo`). Every claim tied to a
   symbol and a test name.
