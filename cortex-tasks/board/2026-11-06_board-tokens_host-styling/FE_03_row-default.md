# FE_03: Row by default

> **Set**: [PLAN.md](./PLAN.md) · **Wave** 2 · **Skills**: cortex-architecture, cortex-docs
> PLAN Decision 6: both (a) and (b). Step 4 also changes the SKILL.md layouts table row that names `column`s.

## Objective

A container written with no layout lays its cards out as `row`. Every stored container keeps its own layout.

## Inputs

`packages/format/schema/events/region.schema.json` (`$defs.region`, `required`), `api/view.schema.json`,
`api/write-item.schema.json`, `common.schema.json` (`mode`); `packages/format/src/view.ts` (`MODES`);
`apps/board/server/write-insert.ts`; the ledger read path (`packages/format/src/ledger-line.ts`);
`skills/vision-board/SKILL.md`; `apps/board/plugin/words/skill-edits.ts`; `docs/specification/` pages that state a
container's mode.

## Steps

1. Failing tests first: a `write_board` container with no `mode` is stored and shown as `row`; a stored `column`
   container stays `column`; a stored line always carries its mode.
2. Contract: make `mode` optional on the sent container only, with `"default": "row"` and the description saying so
   (one home for the default, read by the code). Stored lines keep `mode` required, so the ledger version stays.
3. Code: the write path fills `row` where the sent container has none, in one place.
4. Words: `SKILL.md` and the plugin's skill edits say a container is a row unless the agent names a layout;
   `npm run eval:bot` passes.
5. Update the spec pages that state it (`cortex-docs`).

## Validation

`npm test`, `npm run eval:bot`, `npm run verify`.

## Constraints

Deviation → stop and tell the user. No PII. No commits. Never port 4466. Update this file's notes on completion.
