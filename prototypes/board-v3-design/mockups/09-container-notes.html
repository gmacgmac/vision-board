09 — Container notes: how a note on a whole container is shown

A container takes ONE unsent note (edit or remove until Send; after Send it is read-only history until the agent answers). Today's build shows a "Your note" line under the title line, and it overlaps the kind tabs of the cards below it. Four fixes, each drawn as a small board scene: the noted container plus a second one next to it, so you can see whether anything has to move. Each option shows no note, one unsent note, one sent note waiting for the agent, and a long note. Cards are drawn smaller than on the board; the title line is drawn at real size. Toggle dark and light at the right.

A — Note text on the title line

Numbered pin plus the first words of the note, after the count, cut with an ellipsis. Nothing moves.

Trade-offs. The pin and the start of the note sit on the title line, after the count; the text gives way first, then the count, then the title. No container grows and no card moves, so the overlap with the kind tabs is gone. The price is room: at about 600px a note gets 15 to 18 characters, at 440px almost none, and in a narrow container (last scene) only the pin is left and the count starts to clip. A long note looks the same as a short one, so the full text always needs a click on the text or the pin (the existing bubble). Good for a one-word reminder, poor for a sentence. Sent is told apart only by the quiet pin and the muted text.

B — Count badge on the Comment icon; the icon shows and hides a note block at the top

The maintainer's idea. Left: the note is hidden, the icon carries a badge "1" (a note the agent has not processed yet). Right: the icon was clicked; a note block sits under the title line, above all the cards, pushes them down, and the container below moves down with it (bracket at the left edge, dashed line = where it was).

Trade-offs. The title line gets no extra text at all: the only addition is a 15px badge on an icon that is already there, so it works in the narrowest container. The note is read in full where it lives (the note text, its state, and Edit / Remove while unsent), and a sent note shows as read-only history. The badge counts notes the agent has not processed: an unsent note and a sent one that is still waiting both show "1" (the sent one in the quiet style of the sent pin), and it disappears when the agent answers. The price is layout: showing the block makes the container grow by the height of the block (about 60px for a short note, about 110px for a long one, which is clamped to 3 lines with "Show all"), and everything below it on the board moves down, so showing or hiding a note can shift wires and the view under the person's eyes. A hidden note is not readable at a glance; hover or keyboard focus on the icon shows a short preview without moving anything (last scene).

C — Pin only; the note appears on hover and click

Only the numbered pin sits on the title line. Hover or focus shows a small preview; click opens the existing note bubble. Nothing moves.

Trade-offs. The cheapest title line: one 20px pin after the count, so even a 300px container has room, and nothing can overlap or shift. The note is not readable at a glance, though: with several containers the person must hover each pin to find out which note is which, and a short, a sent and a long note all look alike at rest (first four scenes; the long one is drawn while hovered). The preview is clamped to 3 lines, so a long note needs the click. The bubble is the one the cards already use, so editing, removing and the read-only sent view need no new design. Touch screens have no hover, so there the pin is tap-to-open only.

D — A flag on the top edge of the frame

A small tab stands on the frame's upper edge, in the gap above the container, with a one-line note cut short. Click opens the bubble. Here the noted container is the LOWER one, so the gap between the two containers is where the flag lives.

Trade-offs. The note sits outside the frame, so it cannot touch the title line or the cards, and a flag reads as "attached to this whole container" better than a pin inside it. Nothing inside the container moves. But the flag needs about 24px of free gap above the frame: with the normal 36px between containers it fits, with a tight gap (last-but-one scene, 10px) it lands on the bottom edge of the container above and hides part of it; dragging containers close together will do this often. The flag also needs a free stretch on the top edge between the title and the tool icons (about 150px here); in a container under about 480px wide there is none and it would have to sit over the title line. A long note is cut to about 20 characters, as in A. Stacking the flag completely above the title line (not drawn) would need 44px of gap.
