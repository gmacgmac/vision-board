## `list_boards`

`GET /api/boards` · who: anyone (no credentials) · MCP tool `list_boards`, `vb` command `vb list-boards`

List the project's boards. Call it first: the other tools take a board id. No input, no credentials. Returns `project` (the folder the board has open), `head` (the ledger's latest line) and `boards`, each with `board` (its id), `title`, `seq` (its own latest line) and `locked: true` when the person has locked it (no writes).

### Inputs

| Name | Where | Type | Required | Description |
|---|---|---|---|---|
| `VB-Project` | header | string | no | The folder you work in, as an absolute path percent-encoded the way `encodeURI` does it (the `vision-board` MCP server sends it on every call). When the board server has another folder open, and this folder is not that one or inside it, the call is refused with `wrong-folder` and nothing is read or written. Left out, nothing is checked. |

### Answer

**200**: The boards.

Media type `application/json`.

| Field | Type | Always there | Description |
|---|---|---|---|
| `boards` | list of object | yes | Every board in the project. |
| `head` | integer | yes | The ledger's latest `seq`; 0 when it is empty |
| `project` | string | yes | The folder the board server has open, as the person reads it (`~/projects/example`); every board listed is in its ledger. |
| `ledger` | string | no | The ledger the board server has open in that folder; every board listed is in it. Given only with ledger folders. |
| `readOnly` | `true` | no | Present, and true, while the board server has this ledger open read-only: read it as usual, but every write is refused with `read-only` until the person presses Edit. Left out while it is open for writing. |

Example:

```json
{
  "boards": [
    {
      "board": "roadmap",
      "title": "Where Vision Board goes from here",
      "seq": 41
    }
  ],
  "head": 52,
  "project": "~/projects/example"
}
```

## `get_board`

`GET /api/boards/{board}` · who: anyone (no credentials) · MCP tool `get_board`, `vb` command `vb get-board`

Read one board as it is now. Pass `board`. Returns `head`, the View (regions, nodes and links; meaning only, no coordinates), `state` (the person's answers on each card, pins and modes) and `versions` (each card's latest version), cards keyed by number as a string. Cards are numbered from 1 per board in draw order, never reused; retired cards are left out. When agents write to the board, also open grant `requests` and each region's `holders` (left out when empty). `locked: true`: read it, but don't write (every write answers `locked`). For one node's history, use `show_node`.

### Inputs

| Name | Where | Type | Required | Description |
|---|---|---|---|---|
| `board` | path | string | yes | The board id, from list_boards. |
| `VB-Project` | header | string | no | The folder you work in, as an absolute path percent-encoded the way `encodeURI` does it (the `vision-board` MCP server sends it on every call). When the board server has another folder open, and this folder is not that one or inside it, the call is refused with `wrong-folder` and nothing is read or written. Left out, nothing is checked. |

### Answer

**200**: The board.

Media type `application/json`.

| Field | Type | Always there | Description |
|---|---|---|---|
| `head` | integer | yes | The ledger's latest `seq`; 0 when it is empty |
| `view` | object | yes | One board as the page draws it: meaning only, no coordinates. A node's id is the string form of its number, and every node carries `n`. |
| `state` | object | yes | What the person has done on this board: each item's status, pins, chosen layout modes and card widths, sizes and moves, and the notes on and places of whole containers. |
| `held` | `true` | no | Present, and true, when you hold this board: write on it without asking; `request_grant` would answer `held`. Left out otherwise. |
| `versions` | object | yes | Each node's latest version number, by node id. |
| `requests` | list of object | no | The grant requests on this board the person has not answered, oldest first; left out when there are none. The person answers one with `grant` or `deny` and its `seq`. |
| `boardHolders` | list of object | no | The agents that may write on this board now, creator first; left out when there are none. |
| `holders` | object | no | Region id to the agents that hold it now, creator first; a region with none, and a board with none, are left out. |
| `locked` | `true` | no | Present, and true, while the person has the board locked: it is read-only for everyone, and every write on it is refused with `locked` until the person unlocks it. |
| `readOnly` | `true` | no | Present, and true, while the board server has this ledger open read-only: read it as usual, but every write is refused with `read-only` until the person presses Edit. Left out while it is open for writing. |

Example:

```json

  "head": 52,
  "view": {
    "format": 1,
    "session": "roadmap",
    "version": 52,
    "title": "Where Vision Board goes from here",
    "regions": [
      {
        "id": "review",
        "title": "Review",
        "mode": "grid",
        "columns": 3
      }
    ],
    "nodes": [
      {
        "id": "1",
        "region": "review",
        "kind": "question",
        "title": "Review the rules and principles",
        "body": "Say what is wrong or missing.",
        "n": 1
      }
    ],
    "links": []
  },
  "state": {
    "items": {
      "1": {
        "status": "with-agent",
        "notes": [
          {
            "seq": 50,
            "kind": "comment",
            "text": "Rule 6 needs an example.",
            "at": "2026-10-05T09:12:00Z"
          }
        ]
      }
    },
    "pins": {},
    "modes": {}
  },
  "versions": {
    "1": 2
  }
}
```

## `put_board`

`PUT /api/boards/{board}` · who: the person (the board page cookie) · not offered to agents (`x-agent: false`)

Create a board, or rename one, as the person: `title` and an optional `summary` (left out, the summary is cleared). A new board id creates the board, with no agent creator, so every agent must ask for it with `request_grant` before writing on it; an existing id renames that board; an archived board is refused (`invalid`) until it is restored, and a locked one (`locked`) until it is unlocked. Only the board page calls this, with the person's cookie; an agent that calls it is refused with `forbidden`. It returns the stored ledger line.

### Inputs

| Name | Where | Type | Required | Description |
|---|---|---|---|---|
| `board` | path | string | yes | The board id, from list_boards. |
| `title` | body | string | yes | The board's title. |
| `summary` | body | string | no | One or two sentences on what the board is for. |

Example request:

```json
{

  "summary": "What we charge, and why."

```

## `show_node`

`GET /api/boards/{board}/nodes/{n}` · who: anyone (no credentials) · MCP tool `show_node`, `vb` command `vb show-node`

Read one card with its history. Pass `board` and `n`, the card's number on that board; `linked: true` adds the nodes linked to it, one hop away. Returns every version, the person's notes, replies, proposals, the park bundle if any, links, its container (`region`) and the person's size; a retired card still answers, with `retired`. Read it before you answer a note or redraw a card, to build on the latest version.

### Inputs

| Name | Where | Type | Required | Description |
|---|---|---|---|---|
| `board` | path | string | yes | The board id, from list_boards. |
| `n` | path | integer | yes | The card's number on this board (1, 2, 3... in the order drawn). |
| `linked` | query | boolean | no | True also returns the nodes linked to this one. |
| `VB-Project` | header | string | no | The folder you work in, as an absolute path percent-encoded the way `encodeURI` does it (the `vision-board` MCP server sends it on every call). When the board server has another folder open, and this folder is not that one or inside it, the call is refused with `wrong-folder` and nothing is read or written. Left out, nothing is checked. |

### Answer

**200**: The node.

Media type `application/json`.

| Field | Type | Always there | Description |
|---|---|---|---|
| `n` | integer | yes | The card's number on its board. |
| `board` | string | yes | The board the node is on. |
| `region` | string | yes | The container the node is in now. |

## `act`

`POST /api/boards/{board}/act` · who: the person (the board page cookie) · not offered to agents (`x-agent: false`)

Record one action by the person: ✓ (`ack`), ✗ (`drop`), a note (`comment`; an old `context` is still taken), edit or remove a note not yet sent, save for later, reopen, move, reset, change layout or card widths, resize, grant or deny a request, revoke, send, reject an agent's proposal, archive or restore the whole board, or lock or unlock it, put one card's notes away or bring them back; or allow an app's tools to run at one version of its code (`app-allow` with `app` and `hash`, from list_apps) or stop them (`app-revoke` with `app`), which are on the app, not the board, so a lock doesn't hold them. An archived board is gone for agents, as if it never existed, and every other action on it is refused until it is restored. A locked board is read-only for everyone: every action on it but the person's own marks (flag, unflag, notes-hide, notes-show, archive, restore, unlock) is refused with `locked` (423) until it is unlocked; agents see `locked` on `get_board` and `list_boards`. While the agent is still answering, the message waits and goes when the turn ends; a second Send meanwhile makes it cover both. A `send` whose chat session can't be loaded is a `conflict` (409) whose detail says the chat could not be reached and why; nothing is recorded, so the answers stay unsent and Send can be pressed again. ## `call_app_tool`

`POST /api/apps/{app}/calls` · who: the person (the board page cookie) · not offered to agents (`x-agent: false`)

Run one tool of an app for its panel on the board, and answer the tool's result. Only the board page calls this, with the person's cookie, when the app's panel asks (`tools/call`); an agent that calls it is refused with `forbidden`, because an agent runs its own code itself. The arguments must fit the tool's `inputSchema` (`invalid`). The tool runs in the app's own process, within the limits in docs/specification/apps.md: the person must have allowed this version of the app's code (`needs-approval`); a tool that runs too long is stopped (`app-timeout`); an answer over the size limit is refused (`too-large`); too many calls at once are refused (`app-busy`); a crash, an answer that doesn't fit the tool's `outputSchema`, or an app broken by crashes is `app-failed`; an app with problems is `app-invalid`, and an unknown one `app-not-found`. It answers in MCP's tool-result shape: `content` (the result as text), `structuredContent` (the object the tool returned) and `isError` (true when the tool threw; `content` then holds its message).

### Inputs

| Name | Where | Type | Required | Description |
|---|---|---|---|---|
| `app` | path | string | yes | The app's id: its folder's name in the project's `.visionboard/apps/`. |
| `tool` | body | string | yes | The tool's name, as the app's tools module gives it. |
| `arguments` | body | object | no | The tool's input, checked against its `inputSchema` before it runs. Left out, `{}`. |

Example request:

```json
{
  "tool": "evaluate",
  "arguments": {
    "expression": "12*3"
  }
}
```

### Answer

**200**: The tool's result.

Media type `application/json`.

| Field | Type | Always there | Description |
|---|---|---|---|
| `content` | list of object | yes | The answer as text: the tool's object as JSON, the text it returned, or the message of the error it threw. |
| `structuredContent` | object | no | The object the tool returned, checked against its `outputSchema` when it has one. Left out when it returned text or threw. |
| `isError` | boolean | yes | True when the tool threw. |

Example (An answer):

```json
{
  "content": [
    {
      "type": "text",
      "text": "{\"value\":36}"
    }
  ],
  "structuredContent": {
    "value": 36
  },
  "isError": false
}
```

Example (The tool threw):

```json
{
  "content": [
    {
      "type": "text",
      "text": "There is a \")\" with no \"(\" before it."
    }
  ],
  "isError": true
}
```

### Errors

| Status | Code | When |
|---|---|---|
| 400 | `bad-request` | The request cannot be read: not JSON, a bad id in the path, or a bad query. |
| 403 | `needs-approval` | Only the person calls an app's tools, from its panel on the board (`forbidden`); or the person has not allowed this version of the app's code (`needs-approval`), and the card shows Allow. |
| 404 | `app-not-found` | There is no app with this id in the project (`app-not-found`), or app cards are off (`not-found`). |
| 405 | `method-not-allowed` | The path exists but not for this method. |
| 413 | `too-large` | The body or the batch is over the limit. |
| 415 | `unsupported-media-type` | The body is not application/json. |
| 422 | `app-invalid` | The arguments don't fit the tool's `inputSchema` (`invalid`, each fault in `errors`), or the app has problems to fix first (`app-invalid`; list_apps lists them). |
| 500 | `server-error` | Something unexpected; the detail is in the server log, not here. |
| 502 | `app-failed` | The app's tool failed: its process crashed, its answer doesn't fit its `outputSchema`, or the app is broken after crashing too often (change its code to try again). |
| 503 | `app-busy` | The app has as many calls running and waiting as it may have. Try again when one has answered. |
| 504 | `app-timeout` | The tool ran past its time limit. Its process was stopped, and the next call starts it again. |
