## `list_boards`

`GET /api/boards` · who: anyone (no credentials) · MCP tool `list_boards`, `vb` command `vb list-boards`

List every board in the project with its title and its own last ledger line. Call it first to find the board id the other operations take in their path. It takes no input. It returns `project`, the folder the board has open (`~/projects/example`), `boards` (each with `board`, `title` and `seq`, the board's latest ledger line, and `locked: true` on a board the person has locked, which takes no write) and `head`, the ledger's latest line number. Reads need no credentials.

### Inputs

| Name | Where | Type | Required | Description |
|---|---|---|---|---|
| `VB-Project` | header | string | no | The folder you work in, as an absolute path percent-encoded the way `encodeURI` does it (the `vb` MCP server sends it on every call). When the board server has another folder open, and this folder is not that one or inside it, the call is refused with `wrong-folder` and nothing is read or written. Left out, nothing is checked. |

### Answer

**200**: The boards.

Media type `application/json`.

| Field | Type | Always there | Description |
|---|---|---|---|
| `boards` | list of object | yes | Every board in the project. |
| `head` | integer | yes | The ledger's latest `seq`; 0 when it is empty |
| `project` | string | yes | The folder the board server has open, as the person reads it (`~/projects/example`); every board listed is in its ledger. |

Example:

```json
{
  "boards": [
    {
      "board": "roadmap",
      "title": "Where Vision Board goes from here",
      "seq": 41
    }
  ],
  "head": 52,
  "project": "~/projects/example"
}
```

## `get_board`

`GET /api/boards/{board}` · who: anyone (no credentials) · MCP tool `get_board`, `vb` command `vb get-board`

Read one board as it is now: the full View (regions, nodes and links, meaning only, no coordinates), the person's answers on every node, each node's latest version, and `head`. On a board agents write to, it also carries the open grant requests (`requests`) and each region's holders (`holders`), both left out when empty, and `locked: true` while the person has the board locked: read it as usual, but don't write on it (every write is refused with `locked`). Pass the board id. Use it to see the whole board before you draw on it; use `show_node` for one node's history. `state` and `versions` are keyed by node id, the string form of the card's number on this board. Each board numbers its cards from 1 in the order drawn, and a number is never given again on that board; cards you retired are not on the board.

### Inputs

| Name | Where | Type | Required | Description |
|---|---|---|---|---|
| `board` | path | string | yes | The board id, from list_boards. |
| `VB-Project` | header | string | no | The folder you work in, as an absolute path percent-encoded the way `encodeURI` does it (the `vb` MCP server sends it on every call). When the board server has another folder open, and this folder is not that one or inside it, the call is refused with `wrong-folder` and nothing is read or written. Left out, nothing is checked. |

### Answer

**200**: The board.

Media type `application/json`.

| Field | Type | Always there | Description |
|---|---|---|---|
| `head` | integer | yes | The ledger's latest `seq`; 0 when it is empty |
| `view` | object | yes | One board as the page draws it: meaning only, no coordinates. A node's id is the string form of its number, and every node carries `n`. |
| `state` | object | yes | What the person has done on this board: each item's status, pins, chosen layout modes and card widths, sizes and moves, and the notes on and places of whole containers. |
| `versions` | object | yes | Each node's latest version number, by node id. |
| `requests` | list of object | no | The grant requests on this board the person has not answered, oldest first; left out when there are none. The person answers one with `grant` or `deny` and its `seq`. |
| `boardHolders` | list of object | no | The agents that may write on this board now, creator first; left out when there are none. |
| `holders` | object | no | Region id to the agents that hold it now, creator first; a region with none, and a board with none, are left out. |
| `locked` | `true` | no | Present, and true, while the person has the board locked: it is read-only for everyone, and every write on it is refused with `locked` until the person unlocks it. |

## `put_board`

`PUT /api/boards/{board}` · who: the person (the board page cookie) · not offered to agents (`x-agent: false`)

Create a board, or rename one, as the person: `title` and an optional `summary` (left out, the summary is cleared). A new board id creates the board, with no agent creator, so every agent must ask for it with `request_grant` before writing on it; an existing id renames that board; an archived board is refused (`invalid`) until it is restored, and a locked one (`locked`) until it is unlocked. Only the board page calls this, with the person's cookie; an agent that calls it is refused with `forbidden`. It returns the stored ledger line.

Example request:


## `show_node`

## `show_layout`

`GET /api/boards/{board}/regions/{region}/layout` · who: anyone (no credentials) · MCP tool `show_layout`, `vb` command `vb show-layout`

Read how the board arranges one container, as structure only: the mode and card widths in effect, each card's column and row (and lane in `lanes` mode) by its number on this board, how many of the container's links cross another link, and how many cells are empty. Pass the board id and the region id. | Field | Type | Always there | Description |

## `write_board`

`POST /api/boards/{board}/write` · who: an agent (Bearer secret from `join`) · MCP tool `write_board`, `vb` command `vb write-board`

Pass `items` (at most 200), run in order; each item has a `type`: `board`, `region`, `node`, `link`, `unlink`, `reply`, `propose`, `park`, `retire` or `append`. ## `act`
